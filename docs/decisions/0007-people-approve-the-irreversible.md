# 0007. People approve the irreversible; platform controls enforce it, hooks catch it early

- **Status:** Accepted (revised 2026-10-15 after the fresh-context review)
- **Context:** Agents act fast and people stop reading after many prompts. Some actions can't be undone or change who can do what: moving Live, deleting, granting access, creating keys, connecting apps. A hook in the builder's own editor can be edited or removed by that builder, and Cursor cloud agents don't run MCP hooks, so a hook can't be the control a security team relies on.
- **Decision:** three layers, in this order of trust.
  1. **Enforced by the platforms.** Builders don't hold the 3B push-live permission. Every production space is Git-synced, `main` is protected with a required review and CODEOWNERS, and in Git-synced spaces 3B refuses `push_live` anyway. Automation identities (service accounts) can explore and run, and can ask the in-product agent to build drafts, but can't edit or publish; keep them out of production spaces. `3b-readiness` checks all of this with negative tests.
  2. **Agreed with the person.** Reads run freely. Tenant writes need a numbered plan and a "yes". Connector changes, access grants, API keys and tunnels are done or approved by a person.
  3. **Caught early by the guard hook.** `scripts/hooks/guard.py` runs before every shell and MCP call in both editors (Claude Code `PreToolUse`; Cursor `beforeShellExecution` and `beforeMCPExecution`, fail-closed). It denies: MCP tools that publish, delete, grant, revoke, rotate, connect or disconnect; `git push` to `main`/`master`; `gh pr merge` and merge API calls; force pushes; `3b apps connect|disconnect`; reading the 3B API key; piping or process-substituting downloads into a shell; installing skills outside `bootstrap.sh`; `rm -rf /`.
- **Why:** prose is advisory and hooks are deterministic, but hooks live in files the builder owns, so they're defence in depth ([Claude Code hooks](https://code.claude.com/docs/en/hooks-guide), [Cursor hooks](https://cursor.com/docs/hooks)). A person should always be able to deny a tool call ([MCP spec, tools](https://modelcontextprotocol.io/specification/latest/server/tools)). Approval fatigue erodes review, so gate few things, clearly ([OWASP Agentic Top 10, ASI09](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)).
- **Consequences:**
  - Phase 0 includes GitHub branch protection and the push-live permission check; without them the kit's claims don't hold, and `3b-readiness` says "not ready".
  - MCP tools are matched by name pattern until the tool list is recorded per tenant (`docs/VERIFY.md` V1); anchored patterns avoid false positives such as `list_deleted_workflows`.
  - Cursor's hook payload and output keys aren't in the public docs we've verified; the hook accepts several spellings and emits both (V7).
- **Revisit when:** V1 and V7 close, or the customer's managed settings take over hook distribution.
